# Подключение монтировки к программе Stellarium (протокол LX200)

Для Stellarium используется отдельная прошивка [`src/stellarium_firmware.ino`](../src/stellarium_firmware.ino).
Stellarium видит ESP32 как монтировку **Meade LX200 (compatible)**; связь — по USB (serial, 9600 8N1).
Вся математика (пересчёт углов энкодеров в RA/Dec) и модель привязки считаются на ESP32.
Параметры удобнее всего задавать через веб-интерфейс по Wi-Fi (ESP32 поднимает свою точку
доступа), текстовые команды по serial тоже работают.

## 1. Прошивка

- Arduino IDE → плата **ESP32 Dev Module** → открыть `stellarium_firmware.ino` → загрузить.
- Схема разделов: подойдёт стандартная (по умолчанию) — скетч занимает ~82% её объёма.
  Если планируете доработки, выберите **«Huge APP (3MB No OTA/1MB SPIFFS)»** («Инструменты →
  Partition Scheme») — будет запас. После смены схемы разделов проверьте на странице настроек,
  что сохранённые слоты места и настройки осей на месте.
- USB-порт в прошивке работает на **9600 бод** (на этой скорости его открывает Stellarium),
  поэтому и «Монитор порта» открывайте на 9600.

## 2. Настройка через веб-интерфейс (Wi-Fi)

При включении ESP32 поднимает собственную точку доступа Wi-Fi:

- сеть **`redstar01`**, пароль **`1234567890`**;
- страница настроек: **https://192.168.4.1/** (сертификат самоподписанный)

1. На телефоне или ноутбуке подключитесь к сети `redstar01`. Интернет на этом устройстве
   пропадёт (ESP32 интернет не раздаёт) — это нормально, на время настройки.
2. Откройте в браузере `https://192.168.4.1/`. Браузер один раз предупредит, что
   сертификат самоподписанный: в Chrome — «Дополнительно» → «Перейти», в других браузерах —
   «Принять риск»/«Продолжить». Это безопасно, сертификат вшит в прошивку и действует
   только в этой сети.
3. На странице вверху — живое состояние (время, место, углы энкодеров, RA/Dec), ниже — формы:
   - **Время UTC** — поле для ввода времени в UTC. Кнопка **«Взять время с этого
     устройства»** подставляет в поле текущее время браузера (переведённое в UTC),
     после чего нажмите **«Применить»** — только тогда время попадёт в ESP32;
   - **Место** — **три слота места** (хранятся в памяти ESP32). У каждого слота:
     название (необязательно), широта и долгота (север/восток `+`, юг/запад `-`),
     кнопка **«Взять GPS»** (координаты берутся у браузера — телефон с GPS — и
     подставляются в поля слота; при первом нажатии разрешите доступ к геопозиции),
     кнопка **«Сохранить»** (записать слот в память) и кнопка **«Использовать»**
     (сделать слот текущим местом наблюдения). Текущий, то есть активный, слот
     подсвечен и помечен «используется»; кнопка «Очистить» сбрасывает слот;
    - **Оси** — чекбоксы «Инверсия оси AZM/ALT» (эквивалент `AZDIR -1`/`ALTDIR -1`)
      и нули `AZZERO`/`ALTZERO`; кнопки «AZ = 0 сейчас» и «ALT = 0 сейчас» делают
      текущее положение нулём оси: «ALT = 0 сейчас» нажимайте при горизонтальной трубе,
      «AZ = 0 сейчас» — при трубе, направленной на север (см. §3 «Нули энкодеров»).
      Направления и нули задавайте до привязки: после их изменения точки Sync неверны —
      нажмите `CLEAR` и привяжитесь заново;
   - **Привязка** — таблица сохранённых точек Sync (углы осей, истинные углы,
     невязка) с кнопкой «Удалить» у каждой, кнопка сброса всех точек (`CLEAR`)
     и текстовый `STATUS`.

   Ответы на команды показываются внизу страницы, всё сохраняется в памяти ESP32 так же,
   как при вводе команд по serial.

Wi-Fi и LX200 работают одновременно: Stellarium подключён по USB, а настройки в это же время
задаются со страницы. Wi-Fi-адаптер устройства подключается
только к одной сети, поэтому на время работы со страницей ноутбук будет без интернета
(настройку удобно делать с телефона).

Если включённый Wi-Fi не нужен, его можно отключить: в начале `stellarium_firmware.ino`
замените `#define WEB_UI 1` на `#define WEB_UI 0` и перепрошейте плату.

## 3. Время и место наблюдения (команды serial)

Если веб-интерфейс недоступен, те же параметры задаются текстовыми командами.
Команды вводятся текстом с переводом строки в «Монитор порта» (USB, 9600). Пока с портом
работает Stellarium, команды в него вводить нельзя — вводите команды до подключения
Stellarium (веб-страница по Wi-Fi при этом работает всегда).

| Команда | Пример | Назначение |
|---|---|---|
| `T ГГГГ-ММ-ДД ЧЧ:ММ:СС` | `T 2026-09-17 18:00:00` | время **UTC** |
| `SLOT <n> <широта> <долгота> [название]` | `SLOT 1 55.0583 73.2950 Дача` | сохранить слот места (n = 1..3) |
| `SLOTUSE <n>` | `SLOTUSE 1` | сделать слот текущим местом |
| `SLOTCLEAR <n>` | `SLOTCLEAR 1` | очистить слот |
| `AZDIR 1` / `AZDIR -1` | `AZDIR -1` | направление оси азимута |
| `ALTDIR 1` / `ALTDIR -1` | `ALTDIR 1` | направление оси высоты |
| `AZZERO <град>` | `AZZERO -340` | смещение нуля энкодера азимута |
| `ALTZERO <град>` | `ALTZERO -340` | смещение нуля энкодера высоты |
| `STATUS` | `STATUS` | текущее состояние (в т.ч. список точек привязки) |
| `PTDEL <n>` | `PTDEL 2` | удалить точку привязки с номером n (номера в `STATUS`) |
| `CLEAR` | `CLEAR` | сбросить привязку (точки Sync) |
| `HELP` | `HELP` | список команд |

Место хранится в трёх слотах (команды `SLOT`/`SLOTUSE`/`SLOTCLEAR` или кнопки на
веб-странице), и настройки осей — всё это сохраняется в памяти ESP32 и действует после
перезагрузки: после включения текущим местом сразу становится активный слот.
Время нужно задавать после каждого включения (RTC на плате нет; если команду `T` не задать,
используется время компиляции прошивки как приблизительное).

Пример первичной настройки (ввести по одной строке):

```
T 2026-09-17 18:00:00
SLOT 1 55.0583 73.2950 Дача
SLOTUSE 1
STATUS
```

Широта и долгота должны совпадать с местоположением, выставленным в Stellarium
(окно настроек → «Местоположение»), а время — в UTC.

### Проверка направления осей

`STATUS` (и таблица «Состояние» на веб-странице) показывает для каждой оси три числа.
На примере азимута:

```
Энкодер AZ: raw 7456 (163.80°), после настройки: 163.800°
```

- `raw 7456` — «сырые» шаги энкодера, 0…16383 на полный оборот
  (1 шаг = 360/16384 ≈ 0,022° ≈ 1,3 угловой минуты);
- `(163.80°)` — тот же угол в градусах, ещё без направления и нуля:
  `шаги × 360 / 16384`;
- `после настройки: 163.800°` — угол оси в системе монтировки после `AZDIR`/`AZZERO`:
  `норм(направление × raw° + нуль)`, где азимут нормализуется в 0…360°, а высота — в −180…+180°.

Это ещё **не** реальный азимут и не реальная высота трубы — реальные углы показывает
следующая строка (`Углы монтировки` в `STATUS`, «Монтировка» на веб-странице) уже с
учётом привязки.

Поверните монтировку:

- по азимуту **по часовой стрелке** (вид сверху) — «после настройки» азимута должно расти;
- труба **вверх** — «после настройки» высоты должно расти.

Если растёт в обратную сторону — задайте `AZDIR -1` и/или `ALTDIR -1`.

### Нули энкодеров (AZZERO/ALTZERO)

Энкодер — абсолютный датчик в пределах одного оборота: он всегда выдаёт 0…16383 шагов,
но где у этого оборота «ноль» — зависит только от того, как при сборке поставлен магнит
относительно оси, и с механикой монтировки никак не связано. Нули `AZZERO`/`ALTZERO`
сдвигают шкалу энкодера так, чтобы её ноль оказался в удобном месте; значения хранятся
в памяти ESP32.

**В каком положении трубы выставлять нули:**

| Ось | Положение трубы | Действие | Зачем |
|---|---|---|---|
| Высота (ALT) | труба горизонтально, смотрит на горизонт (проверить уровнем) | кнопка «ALT = 0 сейчас» (или `ALTZERO`) | ход трубы ложится вокруг 0° и целиком остаётся в одной половине шкалы |
| Азимут (AZ) | труба направлена на север (например, на Полярную) | кнопка «AZ = 0 сейчас» (или `AZZERO`) | «после настройки» отсчитывается от севера (удобно читать, на точность не влияет) |

Кнопки учитывают инверсию осей (`AZDIR`/`ALTDIR`) автоматически. Если задаёте команды
вручную, знак зависит от направления: при `ALTDIR 1` это `ALTZERO -<raw°>`, при
`ALTDIR -1` — `ALTZERO +<raw°>` (для азимута так же).

**Почему у высоты это важно, а у азимута — почти нет.** Круговую шкалу нельзя превратить
в число без разрыва: у азимута он в 0°/360°, у высоты — в ±180° (см. «Проверка направления осей»).

- У азимута разрыв безобиден: азимут — окружность, и прошивка всегда сравнивает углы по
  короткой дуге. `AZZERO` нужен в основном для удобства.
- У высоты разрыв опасен: если он попадает внутрь реального хода трубы, «после настройки»
  посреди движения перескакивает на 360° (например, `+179,9°` → `−179,9°`). Точки Sync по
  разные стороны разрыва модель видит как разнесённые на ~360°, и крест визирных нитей
  скачет или уезжает. Обнуление при горизонтальной трубе уводит ход от разрыва на 180°.

Обычно нули можно не трогать: первая же привязка (Sync) вычитает постоянное смещение.
Проверить просто: медленно проведите трубой через весь реальный ход и следите за «после
настройки» высоты — если перескока через ±180° нигде нет, всё в порядке.

Порядок: сначала `AZDIR`/`ALTDIR` и нули, затем Sync. После изменения направления или
нуля старые точки Sync становятся неверными (в них записаны прежние показания осей) —
сделайте `CLEAR` и привяжитесь заново.

Если труба уходит за вертикаль (перевал через зенит или надир), прошивка считает
координаты отражёнными: азимут +180°, высота 180°−высота. Это та же самая точка неба,
поэтому крест визирных нитей продолжает ехать, а не замирает в зените.

### Точность времени и места

Время и место входят в расчёты одинаково — только через звёздное время
`LST = GMST(UTC) + долгота`. Если LST в ESP32 и Stellarium различаются, крест визирных
нитей оказывается повёрнут вокруг оси мира на этот угол: **у Полярной ошибки нет**,
а к небесному экватору она растёт и достигает максимума (внешне это похоже на «крест
не попадает по азимутальной сетке»). 1 секунда времени = 15 угловых секунд неба,
1 минута = 15 дуговых минут, 1 час = 15°; 1 дуговая минута долготы равна 4 секундам
времени. Ошибка широты даёт смещение того же порядка, что и сама ошибка.

| Расхождение времени | Поворот неба | Ошибка у экватора | Ошибка при δ = 45° |
|---|---|---|---|
| 1 с | 15″ | 15″ | 11″ |
| 10 с | 2,5′ | 2,5′ | 1,8′ |
| 30 с | 7,5′ | 7,5′ | 5,3′ |
| 1 мин | 15′ | 15′ | 10,6′ |
| 5 мин | 1,25° | 1,25° | 53′ |
| 1 час | 15° | 15° | 10,6° |

Для визуальных наблюдений держите ошибку наведения не больше ~1/3 поля зрения окуляра.
Отсюда допустимое расхождение времени: обзорный окуляр (поле ~2°) — до 2–3 минут,
25 мм (~1,4°) — до 1,5–2 минут, 10 мм (~0,6°) — до 40 секунд. Практический ориентир —
**не больше 10 секунд**: это ошибка ≤2,5′ у экватора (у Полярной её нет) и меньше одного
шага энкодера (14 бит ≈ 1,3′), точнее выставлять смысла нет.

- **Время** проще всего брать кнопкой «Взять время с этого устройства» (часы телефона
  или ноутбука синхронизированы по NTP), затем «Применить». Если вводите вручную —
  только UTC: ошибка на местный часовой пояс — 15° на каждый час.
- Часы компьютера со Stellarium тоже должны быть синхронизированы (Linux:
  `timedatectl status` должен показывать синхронизацию). Собственный дрейф ESP32 и
  компьютера за ночь — доли секунды, им можно пренебречь.
- Если в Stellarium время сдвинуто вручную или ускорено, ESP32 об этом не знает:
  задайте тот же момент командой `T` (при ускоренном времени совпадения не будет в принципе).
- **Долгота**: GPS с телефона (±10 м) даёт запас в сотни раз; даже ошибка 0,1° (единицы
  километров) даёт ≤6′. Следите только за знаком: восток `+`, запад `-` — перепутанный
  знак разворачивает крест на десятки градусов.
- **Широта**: ошибка даёт примерно такое же смещение по высоте; GPS здесь тоже с запасом,
  а карта с точностью до ~10 км — ≤5′. Не перепутайте широту с долготой местами.

Порядок настройки: сначала время (`T`), активный слот места (`SLOTUSE`) и настройки осей
(`AZDIR`/`ALTDIR`, нули — см. ниже), потом Sync. Точки привязки считаются по текущим
времени, месту и показаниям осей: если исправить их после привязки, модель станет
неверной — сделайте `CLEAR` и привяжитесь заново.

## 4. Подключение по USB

Порт определяется автоматически:

- **Windows**: после установки драйвера CP210x или CH340 (в зависимости от платы) в
  «Диспетчере устройств» появится `COMx`.
- **Linux**: `/dev/ttyUSB0` (или `/dev/ttyACM0`). Пользователь должен быть в группе `dialout`
  (`sudo usermod -aG dialout $USER`, затем перелогиниться).
- **Linux, важно**: имя `/dev/ttyUSBx` не постоянно — после переподключения платы или сбоя
  USB номер может измениться (`ttyUSB0` → `ttyUSB1`), и Stellarium, запомнивший старый путь,
  перестанет подключаться с ошибкой `cannot open serial device`. Указывайте стабильный путь
  из `/dev/serial/by-id/` (он не зависит от порядка перечисления):
  ```
  ls /dev/serial/by-id/
  # usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0
  ```
- **Stellarium из snap** (`stellarium-daily`, имя snap может отличаться): нужно один раз разрешить доступ к USB-serial:
  ```
  sudo snap connect stellarium-daily:raw-usb
  ```

### Настройка телескопа в Stellarium

1. `F2` → плагин **«Управление телескопом»** (Telescope Control) → «Настроить»
   (или `Ctrl+1` — окно «Телескопы»).
2. «Добавить новый телескоп».
3. «Телескоп управляется:» → **«Stellarium, напрямую (через послед. порт или сеть)»**.
4. «Модель устройства:» → **LX200 (compatible)**.
5. «Соединение:» → **«Послед. порт»** (не «Сеть (TCP)»).
6. «Последовательный порт:» → `COMx` / `/dev/ttyUSB0` (Linux: лучше путь из
   `/dev/serial/by-id/`, см. §4).
7. «Равноденствие» → **J2000 (по умолчанию)** — прошивка отдаёт координаты в J2000.
8. «Задержка подключения» — по умолчанию 0.5 с.
9. Сохранить и нажать **«Подключить»**.

После подключения в небе появится крест визирных нитей телескопа. Пока не сделано
ни одного Sync, крест стоит на полюсе мира (рядом с Полярной) и двигается вместе с
ручками монтировки: прошивка считает, что в момент включения труба смотрела на полюс.
Если монтировка выставлена по уровню и при включении труба смотрела на Полярную, можно
наводиться даже без привязки — первый Sync заменяет эту грубую модель точной.

## 5. Привязка к звёздам

Пока нет ни одной точки Sync, прошивка считает, что в момент включения (или после `CLEAR`)
труба смотрела на полюс мира: крест визирных нитей стоит у Полярной и следует за монтировкой.
Первый Sync заменяет эту грубую модель. Удобный порядок: наведите трубу на Полярную и
сделайте первый Sync по ней, затем уточните привязку по 1–2 звёздам в другой части неба.

1. Убедитесь, что время (UTC) и место в ESP32 совпадают с настройками Stellarium
   (см. §3 «Точность времени и места»).
2. Наведите монтировку на яркую звезду и отцентрируйте её в окуляре.
   - Привязку делайте, когда труба **ниже зенита** (не на перевале): модель поправок
     считает высоту от обычного положения оси, и Sync на перевале сдвинет её для всего неба.
3. Выберите эту звезду в Stellarium (клик по звезде).
4. Нажмите **`Ctrl+Shift+1`** — «Синхронизировать телескоп #1 с выбранным объектом»
   (в окне «Навести» это кнопки «Текущий объект» → «Синхронизировать»).
5. Повторите шаги 2–4 для 2–3 звёзд, разнесённых по небу (можно и больше, всего
   хранится до 6 точек).
   - 1 звезда — постоянные смещения по осям;
   - 2 звезды — те же смещения, усреднённые по двум точкам;
   - от 3 звёзд — линейная модель ошибок (МНК по всем сохранённым точкам).
6. Для наведения на объект выберите его в Stellarium и нажмите `Ctrl+1` — крест визирных
   нитей покажет цель, а трубу подводите вручную по разнице положений.
7. Сбросить привязку (например, после переборки монтировки) можно командой `CLEAR`
   по serial или кнопкой на веб-странице. После сброса крест снова отсчитывается
   от полюса, причём полюсом считается текущее положение трубы.

Повторный Sync рядом с уже привязанной звездой (в пределах ~5° по углам осей)
**обновляет** её точку, а не добавляет почти такую же вторую: если после наведения
крест не совпал со звездой, просто наведитесь точнее и нажмите Sync ещё раз — это
безопасно. Когда набрано 6 точек, новый Sync в стороне заменяет самую старую.
Состав точек и невязку (ошибку модели в каждой точке) показывает `STATUS` и таблица
«Привязка» на веб-странице; там же точку можно удалить кнопкой, а по serial —
командой `PTDEL <номер>`.

Совет: после каждого Sync проверяйте точность у этой же звезды — крест визирных нитей
должен совпасть со звездой. Если уехало — нажмите Sync ещё раз.

## 6. Частые проблемы

| Симптом | Причина/решение |
|---|---|
| В Stellarium нет порта в списке | Linux: нет прав (`dialout`), для snap не выполнен `snap connect ...raw-usb`, кабель без данных (charge-only) |
| Порт занят / не подключается | Открыт «Монитор порта» (закройте его) или другой программой |
| После «Отключить» повторно не подключается, в логе `cannot open serial device` | Плата переподключилась под другим именем (`/dev/ttyUSB0` → `/dev/ttyUSB1`) — укажите порт из `/dev/serial/by-id/...` (см. §4) |
| Страница `https://192.168.4.1/` не открывается | Устройство не подключено к сети `redstar01` (Wi-Fi смотрит в другую сеть); проверьте, что залита именно эта прошивка |
| Браузер пишет «Подключение не защищено» / ругается на сертификат | Так и задумано: сертификат самоподписанный и действует только в этой сети. Нажмите «Дополнительно» → «Перейти» (Chrome) или «Принять риск» (другие браузеры) |
| Нет запроса GPS-координат | Разрешите доступ к геопозиции для браузера в настройках телефона; на компьютере без GPS-модуля координаты могут быть определены по Wi-Fi/сети — это неточно |
| Скетч не собирается: «Sketch too big» | Выбрана слишком маленькая схема разделов: возьмите стандартную или «Huge APP (3MB No OTA/1MB SPIFFS)» (см. §1) |
| Крест визирных нитей дёргается и «улетает» | Не выбран слот места (`SLOTUSE`) или не задано время (`T`), либо неверное направление осей (`AZDIR`/`ALTDIR`), либо большие ошибки привязки (см. §3) |
| Крест скачет/уезжает, когда труба проходит определённое место: в `STATUS` «после настройки» высоты перескакивает ≈+180° → −180° | Разрыв шкалы высоты попал внутрь хода трубы: поставьте трубу горизонтально, нажмите «ALT = 0 сейчас» (или задайте `ALTZERO`), затем `CLEAR` и Sync заново (см. §3 «Нули энкодеров») |
| Привязка «сломалась» после смены `AZDIR`/`ALTDIR`/`AZZERO`/`ALTZERO` | Точки Sync хранят прежние показания осей: сделайте `CLEAR` и привяжитесь заново |
| Крест визирных нитей не двигается | Выбран не тот порт; залита прошивка SkySafari (у неё другой протокол); в Stellarium выбран «Сеть (TCP)» вместо «Послед. порт» |
| Большие промахи | Не задано время UTC (`T`), не совпадает место (координаты активного слота), неверные `AZDIR`/`ALTDIR`, мало звёзд привязки или они расположены близко друг к другу |
| Крест повёрнут вокруг Полярной: у полюса совпадает, к экватору сильно уезжает | Разошлось звёздное время: неточное время (`T`) или долгота (активный слот); 1 мин времени = 15′ у экватора (см. §3). Если исправлено после привязки — `CLEAR` и Sync заново |
| Крест смещён по высоте почти одинаково по всему небу | Неверная широта (активный слот) или ошибки привязки |
| Привязка «слетела» после выключения | Так и задумано: точки Sync хранятся только в RAM; слоты места и настройки осей сохраняются |

## 7. Примечания

- Stellarium не передаёт на монтировку ни время, ни координаты места — их надо задать
  на веб-странице или командами (`T`, `SLOT`/`SLOTUSE`).
- Веб-интерфейс живёт только по Wi-Fi: USB-порт ESP32 — это обычный последовательный порт,
  браузер по нему открыть страницу не может.
- Пока нет точек привязки, координаты считаются от полюса мира (см. §5); это не «ошибка»
  и не требует настройки — первый Sync переводит прошивку на обычную модель.
- GPS-координаты берутся с устройства, на котором открыта страница (телефон с GPS), и
  подставляются в поля слота (сохранение — командой `SLOT`): браузеры отдают геолокацию
  только по HTTPS, поэтому страница отдаётся по HTTPS с самоподписанным сертификатом.
  На адрес `http://192.168.4.1/` устройство отвечает редиректом на HTTPS.
- Прошивка не поддерживает TCP-подключение LX200 (хост:порт) — используйте «Послед. порт»
  (USB).
- Рефракция не моделируется; для push-to точности это несущественно.
